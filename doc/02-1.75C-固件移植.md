# 1.75C 固件移植

## 1. 目标硬件

Waveshare **ESP32-S3-Touch-AMOLED-1.75C**：

| 项目 | 参数 |
|---|---|
| SoC | ESP32-S3R8，Xtensa LX7 双核，240 MHz |
| 内存 | 512 KB SRAM、384 KB ROM、8 MB 叠封 PSRAM |
| Flash | 32 MB |
| 屏幕 | 1.75 英寸 AMOLED，466×466，16.7M 色 |
| 显示驱动 | CO5300，QSPI |
| 触摸 | CST9217，I2C（地址通常 0x5A，需实测确认） |
| 电源管理 | AXP2101 |
| IMU | QMI8658（当前 1.75 固件未使用） |
| 音频 | ES7210 ADC + ES8311 codec（当前 1.75 固件未使用） |
| 存储 | 无 microSD |
| 电池 | 3.7 V Li-ion，MX1.25；33691 含电池，33692 不含 |

## 2. 与 1.75 的引脚差异

依据微雪官方 1.75C 的 `pin_config.h`：

| 信号 | 1.75C | 上游 1.75 | 本移植 |
|---|---|---|---|
| LCD SDIO0–3 | 4/5/6/7 | 4/5/6/7 | 不变 |
| LCD SCLK / CS | 38 / 12 | 38 / 12 | 不变 |
| **LCD RESET** | **1** | **39** | 已改 |
| I2C SDA / SCL | 15 / 14 | 15 / 14 | 不变 |
| 触摸 INT | 11 | 11 | 不变 |
| **触摸 RESET** | **2** | **40** | 已改 |
| microSD | 无 | GPIO 1/2/3/41 | 删除 SDMMC 定义 |
| Flash | 32 MB | 16 MB | FQBN 用 32M，分区仍为 16MB 布局 |

上游 1.75 固件里这两个复位脚是实际使用的：

- `src/core/DeviceContext.h:39` 把 `LCD_RESET` 传给 CO5300；
- `src/pages/IncomingCall.h:26` 调用 `touch.setPins(TP_RESET, TP_INT)`。

因此在 1.75C 上直接刷 1.75 固件会复位到错误的 GPIO。移植层通过覆盖 `pin_config.h` 修正。

## 3. 移植层结构

```
ports/175c/
├── pin_config.h          1.75C 引脚覆盖
├── build.py              跨平台构建脚本
├── build.sh              macOS/Linux 入口
├── build.ps1             Windows 入口
├── dist/                 固件产物（忽略）
├── diag/battery_probe/   AXP2101 电池探针
└── README.md
```

构建流程：

1. 复制 `MotoNav_stopwatch/firmware/boards/175/MotoNav` 到 `.build/MotoNav`；
2. 用 `ports/175c/pin_config.h` 覆盖；
3. 调用 arduino-cli 编译；
4. 打包 `app_0x10000.bin`、`full_0x0.bin` 和 manifest。

上游 `MotoNav_stopwatch/firmware` 不被修改。

## 4. 编译

### 4.1 前置环境

- Arduino CLI 1.5.1；
- ESP32 Arduino Core 3.3.10；
- 中国网络可安装 `3.3.10-cn` 变体（核心代码相同，工具链走 `dl.espressif.cn`）。

```bash
brew install arduino-cli

  --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json

arduino-cli core install esp32:esp32@3.3.10-cn \
  --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index_cn.json
```

```bash

./build.sh --jobs 8
```

## 5. 烧录

### 5.1 识别设备

```bash
ESPTOOL="$HOME/Library/Arduino15/packages/esp32/tools/esptool_py/5.3.0-cn/esptool"

"$ESPTOOL" --chip esp32s3 -p /dev/cu.usbmodem2101 chip_id
"$ESPTOOL" --chip esp32s3 -p /dev/cu.usbmodem2101 flash_id
```

1.75C 实测：

```
Chip type: ESP32-S3 (QFN56) (revision v0.2)
Features: Wi-Fi, BT 5 (LE), Dual Core + LP Core, 240MHz, Embedded PSRAM 8MB
USB mode: USB-Serial/JTAG
Detected flash size: 32MB
```

### 5.2 完整镜像（首次安装）

```bash
cd ports/175c

"$ESPTOOL" --chip esp32s3 -p /dev/cu.usbmodem2101 -b 921600 \
  write_flash 0x0 \
  dist/MotoNav_175c_v7.12.11-175c.1_panel0_full_0x0.bin
```

完整镜像会覆盖 bootloader、分区表和应用，**会清空原有设置和数据**。

### 5.3 仅应用（升级）

```bash
"$ESPTOOL" --chip esp32s3 -p /dev/cu.usbmodem2101 -b 921600 \
  write_flash 0x10000 \
  dist/MotoNav_175c_v7.12.11-175c.1_panel0_app_0x10000.bin
```

分区一致时保留 NVS 和配对信息。

### 5.4 重要：不要强制 QIO

镜像头是 **DIO / 80 MHz / 32 MB**。烧录时不要附加：

```text
--flash_mode qio
```

否则会出现：

```
rst:0x7 (TG0WDT_SYS_RST)
ets_loader.c 79
```

ROM 反复重启，应用起不来。直接 `write_flash 0x0 <image>`，让 esptool 读取镜像头参数即可。

### 5.5 启动确认

- 串口持续输出 `rst:0x7` 说明仍在重启循环；
- 正常启动后串口安静，BLE 广播 `MotoNav-D111`；
- 手机 App 能显示 `MotoNav-D111 已连接 / 已配对验证`。

## 6. 电池诊断

`ports/175c/diag/battery_probe/battery_probe.ino` 是只读探针，打印 AXP2101 状态：

```
S1=0x38 S2=0x33 present=1 vbusGood=1 chgState=1 battMv=4207 pct=20..27
```

| 项目 | 含义 |
|---|---|
| `S1=0x38` | bit3=1 电池存在；bit5=1 VBUS 正常 |
| `S2=0x33` | bit5=1 正在充电；低 3 位=3，CV 恒压阶段 |
| `battMv=4207` | 4.207 V，接近 4.2 V 满电 |
| `pct=0xA4` | 电量计百分比，曾只有 20–27% |
| `0x18=0x0A` | 电量计已使能 |
| `0xA2=0x00` | 电量计控制寄存器；改为 0x01 后百分比仍偏低 |

结论：电池和充电通路正常，问题在 AXP2101 电量计的 SOC 估算未校准/未学习。充满后 App 曾显示 100%，说明电量计已恢复。若再次出现电压正常但百分比很低，可做完整充放电循环，或在移植层改为按电压估算百分比。

## 7. 已知限制

- 1.75C 是 32 MB Flash，但 Arduino Core 3.3.10 对 ESP32-S3 只提供到 16 MB 的分区方案；当前只使用前 16 MB。
- 1.75C 没有 microSD，移植层删除了 SDMMC 定义；1.75 固件本身也没有使用 SD。
- StopWatch 专属硬件模块（双实体键、M5PM1 关机、外置 RX8130 RTC）不在 1.75C 固件中；倾角仪表已用 QMI8658 重写，离线时钟已改用 ESP32-S3 内部 RTC。
- 官方 1.75C 示例使用 Arduino-ESP32 3.3.11；本移植固定 3.3.10。
- 没有在真实 1.75C 上完成屏幕、触摸、导航、音频的全量验证。
- 上游许可为非商业使用条款，Avatar 组件为 AGPL-3.0；公开分发需保留许可和来源。
