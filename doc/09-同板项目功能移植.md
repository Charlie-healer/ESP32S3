## 0. 结论

「同一块板 + 同一用途（1.75C 圆屏导航）」的严格交集只有
`mx3353672833-debug/moto-gps-waveshare`。审计后发现本工程固件**已经有完整的
底图层**：手机端发的是高德截图分类后的栅格图（街区/道路/绿地/水面/建筑屋顶+轮廓），
`src/map/` 里矢量底图、主题、路线、HUD、建筑能力握手 `CAP,BLD` 全都在，
所以 moto-gps 的「灰色路网 + 建筑」不是缺口，重复移植只会增加带宽和复杂度。

真正缺的五项，都已移植并烧录验证：

1. **QMI8658 航向融合**（来自 moto-gps）——手机 GPS 朝向做绝对基准，
   陀螺仪补足两次定位之间的 200 ms，转弯时地图转动更跟手。
2. **AXP2101 电源轨与充电默认值**（来自 The-Badge，同板 MIT）——
   关掉 12 条未使用电源轨，修正「充到 60% 就报满」的终止电流和 2.6 V 截止电压。
3. **CST9217 触摸芯片深睡**（来自 The-Badge）——熄屏后发 `0xD1 0x05`，
   亮屏用 RST 唤醒并重新初始化，补上熄屏期间的触摸扫描功耗。
4. **玩具层：4 个游戏 + 水波纹**（来自 The-Badge，MIT）——Bricks /
   Pinball / Marble / Pop / Water，入口是主页的 TOY 按钮；物理规则保留，
   LVGL 绘制换成 Arduino_GFX。
5. **ADS-B 飞机雷达**（来自 capsule-radar，MIT）——手机端取数、算相对
   坐标，BLE bulk type 5 转发；圆屏只解析和绘制，不开 WiFi，静态内存
   只增加 1.15 KB。详见 §7。

未移植的两项（录音、BLE 触控板）各有硬性依赖，原因见 §5。

## 2. 航向融合

### 文件

| 文件 | 作用 |
|---|---|
| `ports/175c/overlay/src/nav/HeadingFusion.h` | 新增；融合类、重力投影、轮询函数 |
| `ports/175c/overlay/src/map/MapFrame.h` | 新增 overlay 副本；在每帧开头轮询并锚定 |
| `ports/175c/overlay/MotoNav.ino` | `setup()` 里 `leanInit()`，让 IMU 在导航前就绪 |

### 行为

- 手机 `#p` 每来一帧定位，用 `posHdg` 和 `posKmh` 做一次 `anchor()`；
- 每帧地图绘制前读一次 QMI8658 加速度+陀螺仪，按
  `-(g·ω)/|g|` 投影出顺时针航向角速度，积分到 `headingFusion`；
- 地图目标朝向优先用融合值（要求定位在 2.5 s 内、陀螺仪样本在 700 ms 内），
  否则回退到原来的 `predictPose()` 外推值；
- 停车（< 0.6 m/s）冻结积分，避免零偏让车头自己转；
- 起步（> 1.5 m/s）第一次移动朝向直接重置为手机朝向；
- 行驶中按 28% 增益向手机朝向纠偏，偏差 > 80° 时用 65%，避免急弯被硬拉。

### 为什么不会装反

角速度投影到实测重力方向，再取负号，得到的是「绕物理上方顺时针」的角速度。
无论屏幕朝上、竖直安装还是软件旋转 0/90/180/270，符号都一致——这是
moto-gps `motion_heading_axis.hpp` 的核心结论，本工程原样保留。

## 3. AXP2101 电源轨与充电

### 文件

| 文件 | 作用 |
|---|---|
| `ports/175c/overlay/src/power/PmicConfig.h` | 新增；`pmicConfigure()` |
| `ports/175c/overlay/MotoNav.ino` | `batInit()` 之后调用一次 |

### 改了什么

| 寄存器 | 改前（实测） | 改后（实测） | 含义 |
|---|---|---|---|
| `0x80` DCDC 使能 | `0x0F`（DCDC1-4 全开） | `0x01`（只留 DCDC1=VCC3V3） | 板子只装了 DCDC1；DCDC2-4 无电感，开着会空转 |
| `0x90` ALDO/BLDO 使能 | `0xFF`（8 路全开） | `0x01`（只留 ALDO1=A3V3） | 其余 LDO 未使用 |
| `0x91` DLDO 使能 | `0x01` | `0x00` | 关闭未用 DLDO |
| `0x61` 预充电流 | 125 mA | 25 mA | 过放电池温和唤醒 |
| `0x63` 终止电流 | 125 mA（充电电流 200 mA 的 62%） | 25 mA | 原来约 60% 就被判满 |
| `0x24` 截止电压 | 2.6 V | 3.0 V | 避免锂电过放 |

充电电流本身没动，仍是芯片默认的 200 mA。

## 5. 没有移植的项与原因

### 5.1 light sleep（The-Badge 的最大省电项）

The-Badge 把待机从 11.9 h 提到 19.6 h，靠的是「关面板 + 关未用电源轨 +
light sleep」。前两项已经做了，light sleep 没做，原因：

- The-Badge 自己记录过：LVGL 任务栈在 PSRAM 里，light sleep 半睡 PSRAM
  后唤醒会重启；本工程虽然任务栈在内部 RAM，但 PSRAM 里有约 5 MB 帧缓冲和
  地图缓冲，需要逐项确认 light sleep 的自刷新配置；
- BLE 连接、USB-Serial-JTAG 在 light sleep 下都会断，The-Badge 需要
  `esp_pm_lock` 在录音/BLE 时拉住不让睡；
- 本工程熄屏后本来就有 `IDLE_POWER_OFF_MS=300000`（5 分钟）和断连 2 分钟
  真关机，light sleep 的有效窗口只有 2-5 分钟，收益远小于一块常亮手表。

### 5.2 触摸芯片深睡（已移植）

CST9217 在熄屏后仍持续扫描，电源轨与面板共用 DCDC1，不能单独断电。现在
`pwrKeyBusLocked()` 在关屏后调用 `touchPower(false)`：

- 通过 `TouchDrvCST92xx::sleep()` 发深睡命令 `0xD1 0x05`；
- 开屏时 `touchPower(true)` 先拉低 TP_RESET（GPIO2）10 ms、拉高 60 ms，
  再重新 `touch.begin()`，并重新挂触摸中断；
- 因为 `touchPoll()` 在 `screenDark` 时本来就直接返回，睡眠期间不会去读 I2C；
- 开机自检 `TOUCH_SLEEP_SELFTEST 1` 实测日志：

```text
touch ok
SELFTEST touch sleep/wake
touch asleep
touch wake ok
```

自检已恢复为 0。仍待实体 PWR 键做一次「熄屏→亮屏→触摸」确认，但深睡命令和
RST 唤醒路径已经在同一块板上验证通过。

### 5.3 BLE 触控板与录音（未移植）

- **BLE 触控板**：The-Badge 用 Bluedroid 的复合 HID（Report ID 1 鼠标 +
  ID 2 键盘）和一套独立的 GAP/GATTS 初始化。本工程用的是 Arduino `BLEDevice`
  的 NimBLE HID，现有 Report 是媒体键；要加鼠标 Report 必须改 HID 描述符，
  主机缓存旧描述符，所有已配对手机都要删除配对重来。而且这块板现在同时是
  BLE GATT 导航服务端，触控板控制的是已连接手机，会和导航触摸冲突。
  代码可移植（`app_mouse.c` 的映射算法是纯 C），但风险/收益不划算。
- **录音**：The-Badge 用 ES7210 麦克风 + 24 MB 裸 flash 分区（`rec`，
  subtype `0x40`），IMA-ADPCM 8.1 KB/s，约 52 分钟，导出靠 TinyUSB 伪造
  FAT。本工程只有 ES8311 输出驱动，没有 ES7210 采集；而且当前分区表是
  16 MB `app3M_fat9M`，加 24 MB 录音分区必须改分区表并擦除用户数据。
  没有回放路径，也不适合在导航固件里顺手加。

### 5.4 为什么雷达没有走设备 WiFi

设备当前空闲内部堆约 168 KB，WiFi + lwIP + mbedTLS 要 60–150 KB 内部 RAM，
flash 也要再加 0.7–1.0 MB，还要做配网并处理 BLE/WiFi 共存。手机本来就在旁边、
有网络也有 GPS，所以采用手机取数、BLE 转发的方案；设备端只解析 20 B/架的
紧凑二进制并绘制，不开 WiFi。实现见 §7。

### 玩法与实现

| 玩具 | 规则 | 输入 | 原版对应 |
|---|---|---|---|
| Bricks | 圆形场地、底部弧形挡板、3×5 砖块、3 条命、每轮加速 | 倾斜转挡板，点一下发球 | `app_games.c` Bricks |
| Pinball | 3 个 bumper、左右两个 flipper、掉底减命 | 左右半屏按 flipper，倾斜轻推 | `app_games.c` Pinball |
| Marble | 倾斜滚球进洞，进洞加分换位置 | 倾斜，点一下重新取水平 | `app_games.c` Marble |
| Pop | 六边形排布的气泡，点破计数，全破 0.9 s 后重排 | 触摸 | `app_games.c` Bubble Pop |
| Water | 半分辨率高度场波纹，触摸滴水，每 2.4 s 自动滴一次 | 触摸 | `app_water.c` 的简化版 |

实现要点：

- 所有游戏物理保留原版的碰撞/摩擦/加速思路；Bricks 用 8 ms 子步防止高速
  穿砖，Pinball 用 6 ms 子步；两者都用「重叠量推出」避免卡在物体里反复翻转。
- IMU 轴：屏幕下 = -ax，屏幕右最初按 The-Badge 的 -ay 移植；实机玩 Bricks
  时发现左右相反，已改成 **屏幕右 = +ay**（同一 `right` 被 Bricks / Marble /
  Pinball 共用，所以三个一起修正）。再按 `screenRot`/`rotFree` 旋转到画布；
  进入游戏时取一次当前姿态作为水平零点，所以平放、竖装、旋转 90/180/270
  都不会偏。
- 水波不是原版的 380 粒子 PBF（那需要约 470 KB PSRAM、core1 物理任务和
  80 ms 帧预算），而是 233×233 的显式波动方程，`v += (邻域平均 - h)/4`，
  `v *= 252/256`，`h += v/4`，30 Hz 更新。分配 216 KB PSRAM，离开 Water
  时释放。
- 玩具层只在非导航主页可进入；来电/配对会自动退出回正常流程，PWR 熄屏后
  不再跑物理。

## 7. ADS-B 飞机雷达（已移植，手机转发版）

入口：TOY 菜单第 6 项 `RADAR`。圆屏没有 WiFi，也没有绝对经纬度（`#p` 只有
局部米坐标），所以由手机取数并算好每架飞机相对车的 `dx/dy`，设备只解析和画。

### 数据链路

```text
手机定位/网络
  ├─ adsb.fi / adsb.lol（2 s 轮询）
  ├─ 用车的 lat/lon 把每架飞机换成 dx/dy 米
  └─ BLE 'M' bulk type 5（20 B/架，最多 30 架）
圆屏 parsePlanes() → PlaneRadar 页
```

### 协议

```text
bulk type 5 payload:
  u8 ver = 1
  u8 count (<=30)
  u8 source (0 adsb.fi, 1 adsb.lol)
  u8 reserved
  u16 range_m
  per aircraft, 20 B:
    i16 dx_m          // 东向
    i16 dy_m          // 北向
    i16 alt_ft        // 0x7FFF 未知
    u16 track_cdeg    // 0.01°，0xFFFF 未知
    u16 gs_kt10       // 0.1 kt，0xFFFF 未知
    u16 squawk        // 0xFFFF 未知
    u8  flags         // bit0 地面、bit1 紧急、bit2 军机
    u8  reserved
    char callsign[6]
```

`BulkReceiver` 收齐后回 `K,5,id`，失败回 `N,5,id`。

### 数据源与注意

- **adsb.fi**：`https://opendata.adsb.fi/api/v3/lat/{lat}/lon/{lon}/dist/{nm}`，
  个人非商业、要求署名并链接 `https://adsb.fi/`，约 1 req/s；
- **adsb.lol**：`https://api.adsb.lol/v2/point/{lat}/{lon}/{nm}`，要求带联系
  信息的 User-Agent；代码里用 `MotoNav/8.3.26 (...)`；
- airplanes.live 现在是 contributor-only，手机蜂窝 IP 可能 403，没有采用；
- 手机定位是 GCJ-02，ADS-B 是 WGS84，在中国大陆有约 500 m 偏移；10–50 km
  量程下可接受，要求高就加 WGS84↔GCJ-02 转换。

## 9. 双击缩放、倾角旋转、主题待机背景、重力设置页

这四项来自 `feat/board-m5stopwatch` 的交互更新；BLE v2 三通道在当前 App
里本来就有（`ctrlQueue` / `imgQueue` / `bulkQ` + 去重 + Burst），没有重搬。

### 9.1 地图双击拖动缩放

- 新增 `src/map/MapZoom.h`：`userMapScale`（0.30–3.00）、双击窗口 750 ms、
  拖动灵敏度 75 px / 1.0x、松手 1.5 s 后写 NVS `zoom`；
- `IncomingCall.h` 的 `touchPoll()`：导航/巡航页第一次轻触记录
  `lastMapTapAt`；750 ms 内第二次按下进入缩放，垂直拖动改 `userMapScale`，
  期间禁止换页拖拽；
- `MapFrame.h`：基础比例改为 `0.85 * userMapScale`，再叠加速度因子
  `1 - kmh*0.006/0.85`（0.45–1.0），目标比例 0.15–3.0；手指按住时
  `viewScale` 直接贴手，不做平滑；
- 地图页顶部在缩放时显示 `ZOOM x.xX`（绿色），松手后 1.2 s 内灰色提示。

### 9.2 倾角/G 随屏幕任意角度旋转

`LeanMeter::leanRead()` 把传感器横向/纵向分量 `(ay, -ax)` 按
`rotCosF/rotSinF` 旋转到画布坐标系后再计算 `leanLateral`、
`leanLongitudinal` 和 `leanRaw = atan2(right, az)`。屏幕 0/90/180/270 和
任意角度都与 UI 朝向一致；转屏后建议在 G 页重新按一次 ZERO。

### 9.3 12 主题待机背景 + 重力设置页

- `FullStandby.h` 不再用 4 套 `FULL_PALETTES`，改为
  `THEMES[styleIdx()]` / `THEMES_NIGHT[styleIdx()]`：待机背景的水面、
  绿地、道路、路线、车标和渐隐都跟手机选的地图主题走（12 款 + 夜间）；
  `MapState.h` 的 include 移到了 `HomePage.h` 之前；
- `fullHomeTick()` 发现 `styleIdx()`/`nightOn` 变化会立即重画待机页；
- 设置页 `ROTATE` 行扩成 5 档：`0 / 90 / 180 / 270 / GRAV`。GRAV 时
  `settingsAutoRotTick()` 每 100 ms 读 QMI8658，按
  `atan2(accelY, -accelX)` 平滑旋转整个画布，并画白色十字基准线；
  角度不写 NVS，退出设置后停在最后角度，重启回到上次手动保存的角度。
  平面平放（重力在屏幕法线方向）时保持当前角度，避免桌面误转。

### 9.4 导航稳定性

- `BleLink` 的三通道优先队列、同 key 去重和 Burst 流水线已存在，未改；
- `NaviBridge.attach()` 给 `AMapNavi.occupyLocManager()` 加了 3 次、每次
  120 ms 的软重试，降低刚释放定位客户端后立刻导航的 GPS 争抢失败；
- `exitNavi()` 显式 `CrossFeeder.hideCross()`，退出导航时清掉路口图层。

**验证**：固件编译并烧录，启动 `MotoNav ready`；APK 编译通过。本轮没有
实机跑双击缩放、倾角转屏和 GRAV（需要手指/转动设备），也没有再跑巡航。
